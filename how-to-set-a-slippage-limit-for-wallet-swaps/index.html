How to Set a Slippage Limit for Wallet Swaps

A slippage limit caps how far a wallet swap can move from its quote; set the lowest tolerance that still covers likely price movement before confirmation.

The Blockheight Editors·Sep 30, 2026·3 min read

A slippage limit sets the largest price change a wallet swap will accept between its quote and execution. Set it by checking the quoted output, choosing a minimum amount you would accept, and using the smallest tolerance that keeps that minimum within reach.

Wallets and swap interfaces may label the setting “slippage tolerance” or “maximum slippage.” MetaMask’s help guidance describes it as the expected percentage difference between quoted and executed prices; the transaction can fail if the price moves beyond the limit before it is processed.

What does a slippage limit control?

A slippage limit controls the minimum output accepted by the swap, not the price shown when you first request a quote. For example, if a quote offers 100 tokens and the tolerance is 1%, the transaction generally must return at least 99 tokens to proceed; the exact calculation depends on the swap contract.

The quoted rate already reflects the trade size against available liquidity. That effect, often called price impact, is distinct from slippage: price impact is part of the quote, while slippage is the change after that quote as the transaction waits to execute. For detail on trading and liquidity from a wallet, see how a Base swap works from a wallet.

How should I choose the percentage?

Start with the quote’s minimum output and decide how much less you are willing to receive. Then choose a tolerance that covers plausible movement during confirmation, without accepting a worse result than that minimum implies.

  • For a liquid pair with a steady quote, begin with a low tolerance and check whether the interface’s minimum output matches your limit.
  • For a volatile pair or a busy network, the quote may move before confirmation; a slightly wider limit can help the swap execute, but lowers the minimum output.
  • For a thinly traded token, check the quoted price impact and expected output first. A wider tolerance cannot improve a poor quote; it only allows a larger change after quoting.
  • If the swap fails, review the updated quote before retrying. Raising the limit automatically can let the transaction proceed at a price you would not have chosen.

What is the trade-off between a tight and wide limit?

A tight limit protects the minimum output but makes a transaction more likely to revert if the market moves before execution. A wider limit can improve the chance of completion, while allowing a less favorable execution price; it does not guarantee that the swap will succeed.

MetaMask’s guidance also notes that a failed swap can still consume network fees. Check the token pair, quoted output, price impact, network fee, and slippage setting on the review screen before confirming; after a failed transaction, compare the new quote rather than simply increasing the limit.

What should I check before confirming?

Compare the displayed minimum received with the amount you decided you would accept, then confirm that the selected percentage matches that floor. If the interface shows a warning about price impact or unusual token behavior, treat that as a reason to recheck the quote and token details, not as a prompt to raise tolerance.

The practical rule is to use the lowest tolerance that accommodates the movement you are prepared to accept. The swap will either execute within that limit or fail; the final amount and whether a pending transaction clears remain unconfirmed until the network processes it.
