How to diagnose a pending XMR bridge swap

A pending XMR bridge swap can sit at deposit confirmation, service processing or payout; match its IDs to each chain, check your Monero wallet, then escalate with evidence.

The Blockheight Editors·Sep 29, 2026·2 min read

To diagnose a pending XMR bridge swap, find the last confirmed transaction and identify which step has not produced its next transaction. A “pending” label alone does not show whether the deposit is unconfirmed, the service is processing it or the payout is waiting to be broadcast.

How do I tell where the swap is stuck?

Start with the swap receipt: record its order ID, deposit address, quoted amount and destination address, then compare its status with the transaction IDs shown in your wallet. A service may use separate transactions for deposit and payout, so a confirmed deposit does not establish that the destination transfer has been sent.

THORChain’s documentation describes distinct stages including inbound confirmation, protocol observation, swap processing, outbound scheduling and destination-chain confirmation. That is one protocol’s flow, not a timetable for every service, but it shows why a single “pending” status can cover different waits. For a fuller comparison of service-based swaps and other routes, see xmr bridge.

Match each available transaction ID to the relevant chain’s explorer or wallet. If the deposit is confirmed but there is no payout ID, the service has not shown that it broadcast the outgoing transaction; ask its support for the current stage and the payout ID, if one exists.

What should I check on the Monero side?

Monero’s wallet documentation provides checks for transaction inclusion and confirmations, while the official payment guide explains how a transaction key can help verify a payment. Check your own wallet’s history and sync status first: a payout may be on-chain without appearing in a wallet that has not scanned recent blocks.

  • Confirm that the deposit transaction ID is the one attached to this order.
  • Check the deposit transaction’s inclusion and confirmation status using your wallet or a suitable Monero tool.
  • Verify that the destination address in the receipt matches the wallet you control.
  • If support asks for payment evidence, use a transaction key or proof only through the service’s official support channel.

Monero’s privacy design means a public transaction lookup does not provide the same address-and-amount view familiar from transparent chains. Its documentation describes using a transaction ID, transaction key and destination address together to check a payment. Keep those details private; never share a wallet seed or spend key to resolve a swap.

When should I contact support or wait?

Contact the service when its stated processing window has passed, the receipt and chain record disagree, or a confirmed deposit has no explained next step. Send the order ID, deposit transaction ID, timestamp, source and destination networks, and a brief description of the status shown; do not send recovery phrases or private keys.

Ask support to identify the stuck stage, provide the payout transaction ID if it has been broadcast, and explain the documented refund process if it cannot complete. A pending label does not by itself confirm a failure or guarantee a refund. Until the service confirms the next action, avoid sending a second deposit for the same order; what happens next depends on the service’s response and whether the payout or refund transaction is actually broadcast.
