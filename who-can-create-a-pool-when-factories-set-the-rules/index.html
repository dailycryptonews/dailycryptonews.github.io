Who Can Create a Pool When Factories Set the Rules

Who can create a token liquidity pool on a decentralized exchange? Anyone who meets its factory rules can; funding and token risk determine whether it is useful.

The Blockheight Editors·Nov 19, 2026 · 02:12 UTC·2 min read

Anyone who meets a decentralized exchange’s factory rules can create a token liquidity pool, including someone who did not issue the tokens. In SyncSwap’s published design, the factory’s public creation function sets the access conditions, while token checks and factory registration rules still apply.

That makes the factory’s role central: it controls which pool implementation can be registered, while an open creation function can let users request pools through an approved factory. For background on the wider ecosystem where SyncSwap operates, zksync defi adds context on decentralized finance activity on zkSync.

  • Tokens: a valid pair accepted by the factory.
  • Pool: deployed and registered through an approved factory.
  • Initial liquidity: token deposits that make trading possible and set the starting ratio.

The published BasePoolFactory exposes createPool without caller-based authorization, and rejects identical tokens or a zero address. The Pool Master accepts pool registration from whitelisted factories. That whitelist can limit which implementations join the registry without requiring each user who calls an approved factory to be whitelisted.

Say a trader wants a Classic Pool for two compatible tokens and the issuer has not created one. Under the published factory design, that trader can request the pool through the factory if the pair passes its checks; the deployed contracts and current network rules determine actual access. Pool creation establishes the venue, but it does not supply the tokens traders need to swap.

Initial liquidity is a separate step. Depositors put both assets into the pool, and the starting ratio establishes their initial relative price. Uniswap’s developer documentation describes pools as holding token reserves and updating prices from pool state; deeper reserves also help limit the price impact of a given trade. Uniswap’s pool mechanics offer a useful reference for these reserve and pricing basics.

For everyday use, an existing pool with adequate liquidity is often preferable: creating a second market for the same pair can split trading activity across pools. A new pool fits unmet demand when users need a market with different tokens or terms, but its creator should judge whether enough capital is available and whether the token risks justify that commitment.

The practical answer is open access where the factory allows it, not automatic approval for every token or implementation. Check the deployed factory and its rules before creating; whether the pool attracts enough liquidity and sustained trading remains uncertain.
